# 后台布局与组件决策

设计表单、数据列表、导航、配置与反馈时使用，把组件的选择对应到任务、数据和操作结果，具体外观沿用项目的视觉体系

## 从工作范围确定导航与布局

| 需要解决的问题 | 可选结构 | 检查点 |
| --- | --- | --- |
| 在稳定的业务域之间切换 | 顶部导航或侧边菜单 | 当前模块清楚，常用入口位置稳定，折叠后仍能识别 |
| 查看同一对象的不同信息 | 标签页 | 对象身份始终可见，切换时保留合理的输入和选择 |
| 返回有层级的上级范围 | 面包屑 | 表达真实层级，链接有明确目的地 |
| 完成依赖顺序明确的任务 | 步骤条 | 当前阶段、完成条件、可返回范围清楚 |
| 在列表内核对短详情 | 行展开、相邻面板或抽屉 | 关掉后能继续原来的筛选与阅读位置 |
| 长时间处理复杂对象 | 独立详情或编辑页 | 可直接访问和分享位置，离开前处理未保存内容 |

- 页面按业务范围、标题与动作、查询条件、结果及分页组织，具体层级随任务裁剪，已有导航足以定位时减少重复标题
- 模块背景、内容表面和浮层通过清晰的明暗与边界区分，表格与工具栏共享左右对齐线
- 局部主动作靠近当前对象，一页多个独立任务分别表达其操作层级，数据行里的低频动作可收进更多菜单
- 同级按钮、输入框与选择器使用一致高度，页面密度由行高、单元格留白和控件间距共同调整
- 带单位、前缀或搜索图标的复合输入以外层容器承载边框与焦点，内部输入不重复画轮廓，保留键盘焦点的可见性，分别检查悬浮、错误、禁用及明暗状态的文字对比
- 窄屏先调整导航与操作排列，比较型表格保留受控横滚，固定列占宽须给主要数据留下可读区域

## 让表单说明输入方式与生效时机

- **稳定标签**　每个字段保留可见标签，单位、格式和必要帮助靠近输入，占位内容用于示例，输入完成后标签仍可识别
- **适合任务的排列**　普通录入可先试单列，紧密相关的起止日期或区间可以并排，同组标签对齐，长标签和窄屏可放到字段上方
- **按选择方式选控件**　少量互斥项可直接展示，多选用复选框，大量可检索项使用搜索选择，有层级关系时展示层级与路径
- **明确开关的含义**　独立开关通常表达即时启停，若属于待提交表单，明确保存入口与待保存状态，即时变更失败时恢复原值或显示仍待确认
- **使用可信默认值**　从已知上下文填充值，用户能看见并修改，权限、接收者和影响范围等重要默认值在提交前可核查
- **选择校验时机**　输入过程中避免反复打断，格式错误可在离开字段后提示，提交时检查完整性，异步校验只展示与当前输入对应的最新结果
- **把错误带回现场**　说明哪个条件未满足以及如何修正，提交失败保留有效输入，将焦点引向首个错误，长表单可提供可定位的错误摘要
- **区分重置与清空**　编辑表单的重置恢复哪一版、筛选重置保留哪些默认条件，都应符合可预期的行为，变更较多时提供恢复能力

提交期间通过按钮状态反馈正在处理，重复提交的保护同时落实到服务端，保存成功后的列表、详情和表单应显示一致结果

## 组织可比较、可操作的表格

- **按决策排列字段**　将身份和关键判断字段靠前，数量与金额统一单位及对齐方式，状态文字保持完整，同一数据类型遵守相同格式
- **控制视觉噪声**　常规表格先试表头与横向分隔，长行容易串读时再使用低对比斑马纹，需要逐格比对时再考虑纵向边界
- **让筛选结果可解释**　区分正在编辑的条件与已应用条件，高成本组合查询可统一提交，快速单项筛选可即时更新，搜索请求乱序时以最新条件为准
- **明确分页语义**　排序与筛选若作用于完整结果集，服务端应按完整集合处理，条件变化后校正页码，不能把当前页筛选伪装成全量筛选
- **明确选择范围**　显示选中数量，区分当前页与全部匹配，跨页选中使用稳定对象标识，条件变化时明确选择是否保留
- **稳定行内操作**　高频入口保持位置一致，其他动作收纳，批量操作后给出逐项结果，失败项可定位和重试
- **谨慎截断**　身份、时间、状态和关键操作保留必要信息，长描述可展开或查看详情，关键内容在键盘和触屏下同样可获得
- **区分数据语义**　零值、缺失、尚未加载、无权限与请求失败各自表达，权限错误通过适当提示说明，避免混成空结果
- **保留工作上下文**　从详情返回后尽量恢复筛选、排序、页码与阅读位置，失效或被删除的记录给出相应反馈

固定表头、固定列、列配置和虚拟滚动按实际数据规模与任务引入，验证键盘操作、行高变化、焦点和窄屏行为

## 用反馈的范围与持续性选择组件

| 情形 | 合适的反馈 | 留给用户的下一步 |
| --- | --- | --- |
| 某个字段不符合输入条件 | 字段附近持续显示错误 | 修改该字段，保留其余输入 |
| 轻量操作已完成，如复制成功 | 短时消息，必要时配合局部状态 | 继续当前工作 |
| 当前区域持续受影响，如部分数据过期 | 区域内提示 | 了解影响、刷新或使用可用内容 |
| 后台任务稍后完成 | 通知与可再次查看的任务记录 | 查看或下载结果 |
| 需要明确决策后才能继续 | 气泡确认或对话框 | 看清对象与影响，确认或取消 |
| 任务完成或访问受限构成独立终态 | 结果区域或结果页 | 返回、查看记录或申请访问 |
| 暂无内容或筛选无匹配 | 空态及对应入口 | 创建首项或调整条件 |

- 多个组件表达同一结果时保留必要渠道，字段错误与全局重复弹窗会增加修正成本
- 加载状态作用于实际等待区域，已有内容可用时保留内容并说明刷新中，进度条依据可测量进度更新
- 重要失败与恢复入口保持可访问，短时消息适合无需后续处理的信息
- 提示的颜色配合文字或图标表达含义，屏幕阅读器可获得重要状态变化，常规反馈保持当前输入焦点
- 取消或撤销的范围以实际能力为准，关闭抽屉、停止等待与取消后台任务分别处理，已提交副作用需要对应恢复机制

## 弹层、抽屉与键盘行为

- 抽屉适合依赖列表上下文的查看或轻量编辑，宽度须容纳字段和操作，窄屏可转换为完整页面式布局
- 对话框用于聚焦的决策或短任务，长表单、多层选择与持续工作优先评估独立页面
- 模态打开后焦点进入内部并在其内循环，关闭后回到触发点，非模态侧面板允许按合理顺序访问页面其他内容
- 明确 Escape、遮罩点击和关闭按钮的效果，存在未保存内容时提供可理解的保留或放弃方式
- 搜索选择、菜单和标签页采用组件约定的键盘行为，关键提示有可访问名称，悬浮内容同时提供键盘或点按入口

## 将设计落实到现有组件库

- 先检查项目依赖和已使用版本，沿用其表单状态、主题机制与交互语义，具体 API 按该版本官方文档核对
- 从全局语义变量与组件变量统一品牌色、字号、圆角、尺寸和状态，局部例外有明确场景，避免逐页漂移
- 组件能力决定实现方式，业务语义由任务定义，跨框架迁移时逐项检查表单校验、选中状态、弹层焦点和分页行为
- 以完整路径验收，例如筛选待办、跨页选择、打开详情、修正错误、保存并回到列表，检查沿途上下文与结果是否一致

本文件是任务层面的设计规则，原型中的模拟结果与生产接口行为应在交付说明中明确
